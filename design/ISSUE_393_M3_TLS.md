# Issue #393 M3: TLS, the milestone with no oracle

Design before code. M1 (transport, #605) and M2 (SigV4, #606) are merged. M3
adds TLS so `https://` endpoints work and `s3://` can point at one, which is
what real object stores require. The #393 memo called this the milestone with
"a real defect path and no oracle": there is no byte-exact reference for "did
we verify the certificate correctly", so every check is proven by removal
against a certificate that must be refused.

## Decisions carried from the plan of record (not reopened here)

- **OpenSSL, inside the module only.** The preloaded library links nothing
  new. Detection is `pkg-config --exists openssl` in `objstore/Makefile` only;
  a build without OpenSSL keeps today's exact behaviour (`https://` reports
  unsupported, message extended to say the module was built without TLS).
- **OpenSSL does the verification; we only configure it.** Hand-writing
  hostname matching is the defect path the memo documented (196 lines in
  curl's ossl_verifyhost). Configuration, per the memo, exactly:
  - `SSL_VERIFY_PEER`, chain against the default verify paths
    (`SSL_CTX_set_default_verify_paths`, which honours `SSL_CERT_FILE` /
    `SSL_CERT_DIR` in the environment; that is also how the suite trusts its
    fixture CA, with no test-only code in the module).
  - Hostname binding through `X509_VERIFY_PARAM`: `set1_host` for names,
    `set1_ip_asc` for IP literals (the ordinary MinIO/Garage endpoint form,
    and the case `X509_check_host` alone silently misses), with
    `X509_CHECK_FLAG_NO_PARTIAL_WILDCARDS`.
  - SNI sent for names, suppressed for IP literals.
  - Minimum protocol TLS 1.2.
- **No blocking handshake.** `SSL_connect`/`SSL_read`/`SSL_write` run on the
  existing nonblocking fd; `SSL_ERROR_WANT_READ`/`WANT_WRITE` map onto the M1
  wait loop (`WaitLatchOrSocket` + `CHECK_FOR_INTERRUPTS`), so cancel works
  mid-handshake and mid-body exactly as it does in cleartext.
- **Error-queue hygiene**: `ERR_clear_error()` before each SSL entry and drain
  after failure, per the be-secure-openssl caution about extensions sharing
  the server's OpenSSL error queue (the server may link OpenSSL, as PG18
  does).

## Scheme and endpoint behaviour after M3

- `https://host[:port]/path` is handled when the module was built with
  OpenSSL; default port 443.
- `AWS_ENDPOINT_URL=https://...` is accepted for `s3://`; the M2 refusal
  becomes the composition path (signed requests over TLS).
- Plain `http://` stays supported for explicitly configured trusted-network
  endpoints, per the memo; documentation says https is the expected form.

## Error reporting

All TLS failures are SQLSTATE 08006 naming the URL. The verification detail
carries `X509_verify_cert_error_string(SSL_get_verify_result(...))`, which is
a deterministic OpenSSL string ("certificate has expired", "hostname
mismatch", ...). The suite discriminates the arms on that detail string plus
the 08006, with a premise that the TLS handshake was genuinely reached (the
fixture logs handshake attempts); a bare text grep with no reached-the-code
premise is the trap the house rules name, and the #607 review just
re-demonstrated it.

## The suite: `test/objstore_tls_read.sh`

Fixture PKI generated by the openssl CLI in the suite workdir: CA-1 (trusted
via `SSL_CERT_FILE` in the postmaster environment), CA-2 (never trusted).
Servers, all the same python fixture with an ssl-wrapped socket:

| server | certificate | expectation |
|---|---|---|
| good | CA-1, SAN IP:127.0.0.1 | data flows; differential oracle green |
| wronghost | CA-1, SAN DNS:other.example | 08006, hostname mismatch |
| expired | CA-1, IP SAN, not_after in the past | 08006, certificate expired |
| untrusted | CA-2, IP SAN | 08006, issuer not trusted |

Arms:

- A: `https://` differential oracle against the byte-identical local file on
  the good server (exercises the IP-literal path: `set1_ip_asc`, SNI
  suppressed).
- A2: `s3://bucket/key` with an https endpoint on the good server, SigV4
  verification enabled in the fixture: the M2 signer composed over TLS.
- C: the three refusal arms above, each 08006 + its deterministic reason
  string, each with the premise that the handshake was attempted.
- D: cancel mid-body over TLS (the stall fixture behind the good cert), the
  M1 idiom; proves the WANT_* wait loop services interrupts.
- The M1/M2 suites re-run unchanged: cleartext behaviour is untouched.

## Removal proofs (run and recorded in the PR)

1. **Drop verification** (`SSL_VERIFY_NONE`): the wronghost, expired, and
   untrusted arms all go red (their reads succeed).
2. **Drop hostname binding** (skip `set1_host`/`set1_ip_asc`): the wronghost
   arm goes red (chain verifies, name never checked) while expired/untrusted
   stay green, which isolates the binding as load-bearing independently of
   chain verification.
3. Suite-internal: the good-server arm is the removal proof for
   over-restriction (a configuration that refuses everything cannot pass it).

## Out of scope

Client certificates, CRL/OCSP (curl does neither by default; parity),
wildcard-certificate fixtures (no partial-wildcard server exists to hit the
flag; the flag is set because the memo requires it and it cannot loosen
anything), TLS for the write path (#394), session resumption, and any change
to cleartext behaviour.
